# Bread Pitt Bake Media Workflow

## Purpose

Document the complete lifecycle of bake photos from camera import to published website.

This workflow is designed to make each bake repeatable:

- preserve original photos
- derive website images automatically
- keep captions and filenames connected
- validate content before publishing

## Start Here
1. Create bake directory
2. Add workflow entry
3. Put captions on photos
4. Run abbey media rename-exports
5. Continue pipeline

## Required Before Build

Every bake `story.md` must declare the matching bake ID.

Example:

Directory:

    content/bakes/2026/bake002/

Requires:

    ---
    bake: bake002
    ---

The bake ID in `story.md` must match the bake ID in `bake.yml` and the directory name.

## Directory Lifecycle

    incoming/photos
        |
        v
    media/bakes/YYYY/bakeXXX
    (original project media)
        |
        v
    working/media/bakes/YYYY/bakeXXX
    (processing workspace)
        |
        v
    public/images/bakes/YYYY/bakeXXX
    (published website derivatives)

## Important Rules

- Do not manually rename photos.
- Do not edit files in `working/media`.
- Always run Abbey commands from the Bread Pitt repository root.
- The rename manifest must be generated by the active Bread Pitt project.
- The `working` directory is temporary processing space.
- The `media` directory contains the original project-owned media.

## Complete Workflow

## Step 1 - Create Bake Structure

Create:

content/bakes/YYYY/bakeXXX/
  bake.yml
  photos.yml
  story.md
  media-intake.json

Add workflow entry to:

.abbey/media.yml

Initialize template values:

Replace all placeholders:

- bakeXXX with the actual bake ID
- YYYY with the actual year
- example photo/gallery references with real photos

Verify:

story.md contains:

---
bake: bakeXXX
---

where `bakeXXX` matches the directory name.

## Step 1 - Create Bake Structure

Create:

    content/bakes/YYYY/bakeXXX/
      bake.yml
      photos.yml
      story.md

Add the publication workflow entry to:

    .abbey/media.yml

The bake content should include:

- bake metadata
- photo references
- story content

## Step 2 - Stage Original Photos

Copy original JPG/XMP pairs into:

    media/bakes/YYYY/bakeXXX

These are the original project media files.

Do not rename manually.

Example:

    media/bakes/2026/bake002/

## Step 3 - Create Processing Workspace

Copy original media into:

    working/media/bakes/YYYY/bakeXXX

Example:

    cp media/bakes/2026/bake002/* working/media/bakes/2026/bake002/

The working directory is where Abbey performs processing.

## Step 4 - Rename Exports

Run from the Bread Pitt repository root:

    abbey media rename-exports working/media/bakes/YYYY/bakeXXX

This uses:

- XMP captions
- capture dates
- Abbey filename rules

It creates:

    working/media/bakes/YYYY/bakeXXX/.abbey-rename-manifest.json

Verify the manifest contains:

    project: Bread Pitt
    configuration: /path/to/bread-pitt/.abbey/media.yml

Example:

    /home/bcooke/git/bread-pitt/.abbey/media.yml

If the manifest references Abbey Root instead of Bread Pitt, stop and rerun from the Bread Pitt repository.

## Step 5 - Generate Intake Manifest

Run:

    pnpm bake:intake generate content/bakes/YYYY/bakeXXX

Creates:

    content/bakes/YYYY/bakeXXX/media-intake.json

Review:

- captions
- selected images
- generated filenames

The intake manifest connects the renamed working images to the bake publication process.

## Step 6 - Validate Publication

Run a dry run first:

    abbey media publish bakeXXX --dry-run

Confirm:

- correct source directory
- correct destination directory
- expected derivative list
- no unexpected files

## Step 7 - Publish Website Images

Run:

    abbey media publish bakeXXX

Creates:

    public/images/bakes/YYYY/bakeXXX

and:

    content/bakes/YYYY/bakeXXX/media-publication.json

The publication manifest records:

- source files
- generated derivatives
- hashes
- image dimensions
- metadata removal validation

## Step 8 - Validate Website

Run:

    pnpm build

The build validates:

- Astro content
- bake routes
- story references
- photo references
- generated pages

## Common Failures

### Story has wrong bake ID

Error:

    Bake bake002 story front matter must declare bake: bake002

Fix:

Update:

    content/bakes/YYYY/bakeXXX/story.md

Example:

    ---
    bake: bake002
    ---

## Photos and Galleries

Photo IDs are defined in:

    content/bakes/YYYY/bakeXXX/photos.yml

Story references must match photo IDs:

    {{ photo: hero }}

Gallery references must match gallery IDs:

    {{ gallery: ingredients }}

The website build validates these references.

### Template References Left Behind

Errors may occur if the story still contains template references.

Example:

    {{ gallery: example-comparison }}

Remove unused template references or create the required gallery definition.

## Bake Completion Checklist

- [ ] bake.yml complete

- [ ] original JPG/XMP files stored in media/
- [ ] working directory created

- [ ] publication dry run successful
- [ ] derivatives published
- [ ] media-publication.json created
- [ ] pnpm build passes
